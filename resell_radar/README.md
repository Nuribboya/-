# 리셀 레이더 (ResellRadar)

한정판·콜라보 발매 일정을 모아서 **응모할 가치가 있는 것만** 골라주고, 텔레그램으로
알려주는 윈도우 프로그램입니다. 응모·결제는 직접 합니다 (자동 응모/매크로 기능 없음 —
대부분의 발매처 약관 위반이고 계정 정지 사유입니다).

## 받기

GitHub 저장소의 **Releases → `resell-radar-latest`** 에서 `ResellRadar.exe` 를 받거나,
**Actions → Build ResellRadar.exe → 최신 실행 → Artifacts** 에서 받습니다.

exe 는 아무 폴더에나 두면 되고, 설정과 데이터는 **exe 와 같은 폴더**에 생깁니다.
(처음 실행 시 윈도우 SmartScreen 경고가 뜨면 "추가 정보 → 실행")

## 사용법

더블클릭하면 메뉴가 뜹니다.

1. **처음 실행** — 설정 화면
   - 텔레그램 알림: @BotFather 에서 봇을 만들고 토큰을 붙여넣은 뒤, 그 봇에게 아무
     메시지나 보내면 자동으로 연결됩니다. (알림 없이 쓰려면 엔터)
   - 최소 순수익(기본 30,000원), 최소 수익률(기본 20%)
2. **지금 확인하기** — 수집 → 판정 → 알림을 한 번 실행하고, 결과 화면(`report.html`)을
   브라우저로 엽니다. 카드마다 판정·등급·예상 순수익·마감까지 남은 시간·판정 근거가 나오고,
   추천/애매/패스 탭과 마감 임박순/수익순 정렬이 있습니다. 엑셀용 `latest_report.csv` 도 함께 저장됩니다.
   자동 실행 중에도 `report.html` 은 매번 갱신되므로 메뉴 **5) 마지막 결과 화면 열기**로 언제든 볼 수 있습니다.
3. **3시간마다 자동 실행 등록** — 윈도우 작업 스케줄러에 등록. 컴퓨터가 켜져 있을 때만 돕니다.

명령어로도 실행할 수 있습니다: `ResellRadar.exe run`, `setup`, `schedule --hours 3`, `unschedule`

## 일정 수집처

| 수집처 | 방식 |
| --- | --- |
| 나이키 SNKRS (KR) | 자동 — SNKRS 웹페이지가 쓰는 공개 상품 피드 |
| 럭드 (luck-d.com) | 자동 — 국내 발매 일정·정가와 **제품별 국내 응모처 전체**(응모/선착순, 기간, 온·오프라인, 실제 응모 링크). 신발·의류 카테고리, 상품 페이지는 로컬에 캐시 |
| 무신사 래플 | 자동 — 래플 상세 페이지. 새 래플 번호를 몇 개씩 확인해서 진행 중인 것만 가져옴 |
| 미국 발매 캘린더 (Sneaker News, Sneakerfiles) | 자동 — 각 사이트의 공개 RSS 피드. 기사 본문의 `Release Date`·가격을 읽음 |
| 그 외 (무신사, 크림 드로우, 편집숍, 해외 등) | `releases.csv` 에 직접 입력 |

`releases.csv` 열: 상품명, 발매처, 응모시작, 응모마감, 발매일, 정가, 방식(응모/선착순),
발매처수, 재발매(Y/N), 예상시세, 링크, 메모. 날짜는 `2026-11-01 10:00` 형식.

처음 실행하면 `releases.csv` 에 **2026-10-21 기준 공개 발매 캘린더에서 찾은 콜라보 19건**이
들어 있어 바로 결과를 볼 수 있습니다. 국내 정가를 못 찾은 칸은 비어 있고, 미국 정가만 알던 건
`미국 정가 × 1,150` 으로 추정해 메모에 적어 두었습니다. 발매처 페이지에서 확인해 고쳐 쓰세요.
날짜가 지난 줄은 결과에서 자동으로 빠지고, `(날짜 미정)` 줄은 날짜가 나오면 발매일을 채우면 됩니다.
예전 버전이 만든 예시 한 줄짜리 `releases.csv` 는 이 목록으로 자동 교체되며, 직접 적은 줄이
하나라도 있으면 건드리지 않습니다.
**예상시세에 크림 실제 시세를 적으면** 등급으로 추정한 가격 대신 그 값으로 수익을 계산합니다.

## 국내 응모처 등급

럭드에서 가져온 응모처마다 등급을 매기고, 카드에 **등급 높은 순서로** 응모처 버튼을 보여줍니다.
카드의 큰 버튼은 가장 좋은 응모처의 실제 응모·구매 페이지로 바로 연결됩니다 (제휴 리디렉트 주소는 풀어서 연결).

| 등급 | 기준 | 예 |
| --- | --- | --- |
| S | 브랜드 공식 앱·몰 — 물량이 가장 많고 택배 수령 | 나이키 SNKRS, 아디다스 코리아, 뉴발란스 |
| A | 주요 편집숍 — 인기 협업 물량을 받음 | 카시나, 웍스아웃, 튠, 스컬프, 아트모스 |
| B | 대형 플랫폼·체인 — 응모자가 매우 많거나 일반 발매 위주 | 무신사, 크림, 29CM, W컨셉, SSG, 롯데온, ABC마트, 슈마커 |
| C | 오프라인 방문이 필요하거나 해외(배대지 필요) | 매장 현장 래플, 해외 편집숍 |

- 표에 없는 국내 온라인 응모처는 B(기본값)로 시작합니다.
- **기록 기반 보정**: 응모처가 그동안 푼 제품이 8건 이상 쌓이면, 그중 A− 이상 비율이 30% 이상이면 한 단계 올리고,
  5% 이하면 한 단계 내립니다. 결과 화면 아래 **응모처 등급** 표에 근거·기록 수·A급 이상 비율이 나옵니다.
- 등급표는 `tiers.json` 의 `venues` 에서 고칠 수 있습니다.
- 같은 제품이 나이키 한국 피드(제품 코드 일치)나 `releases.csv`(이름 거의 같음)에도 있으면 럭드 기록 하나로 합칩니다.
  `releases.csv` 에 적은 예상시세와 메모는 넘겨받습니다.
- 응모처 수가 자동으로 "발매처 수" 판정에 들어가고, 국내 응모처 중 하나라도 응모(래플)면 판매 방식이 응모로 잡힙니다.

## 무신사 래플

무신사 래플 페이지에는 **응모자 수와 당첨자 수**가 공개돼 있어서, 카드에 `🎟 당첨 1명 · 응모 34,434명 (확률 0.0029%)`
처럼 실제 당첨 확률을 보여줍니다. 당첨자 수가 곧 실제 물량입니다.

2026년 8~10월 래플 40건을 확인해 보면 대부분 **당첨자 1명에 응모 2만~6만 명**인 이벤트성 래플(아이패드, 향수,
골드바, 1,000원 이벤트 등)이었습니다. 리셀용 한정판 응모처라기보다 경품 추첨에 가깝기 때문에, 응모는 공짜니 넣되
기대는 낮게 잡는 게 맞습니다. 끄려면 `settings.json` 의 `sources.musinsa` 를 `false` 로.

## 국내 일정 추정 (미국 캘린더 → 한국)

미국 캘린더에만 있는 콜라보는 국내 정보가 없으므로 프로그램이 추정합니다. 결과 화면에 **일정 추정** 표시가 붙습니다.

- **발매일**: 미국 발매일과 같은 날로 잡습니다. 미국 오전 10시(동부)는 한국 같은 날 밤이라 국내는 당일~하루 차이입니다.
- **국내 정가**: 처음엔 `미국 정가 × 1,150원`. 같은 제품이 나이키 한국 피드나 `releases.csv` 에 실제 국내가로
  올라오면 그 쌍(미국가, 국내가)을 기록해 두고, 3건 이상 모이면 **중앙값 환산 비율**로 바꿉니다.
  메모에 `추정` 이 들어간 정가는 학습에 쓰지 않습니다.
- **어디서 응모하나**: 브랜드별 국내 판매처(나이키 SNKRS 한국, adidas CONFIRMED, 뉴발란스 공식몰 등)와,
  JJJJound·Supreme·Kith 같은 협업 상대 자체 몰 선발매 가능성을 적어 줍니다.
- **확정되면 교체**: 같은 제품이 나이키 한국 피드나 `releases.csv` 에 나오면 미국 캘린더 항목은 빠지고 국내 정보를 씁니다.
  국내 정가가 비어 있으면 미국 정가로 추정해 채웁니다.
- RSS 피드는 최근 기사 수십 개만 보여주므로, 한 번 잡힌 발매 정보는 발매일까지 기억해 둡니다.
- 미국 캘린더에서는 **협업(` x `)·등급표의 협업 상대·인기 실루엣**만 가져오고 일반 컬러웨이는 거릅니다.
- 끄려면 `settings.json` 의 `sources.us_calendar` 를 `false` 로.

## 판정 방식

등급은 **C− ~ S+ 12칸**입니다 (C−, C, C+, B−, B, B+, A−, A, A+, S−, S, S+). 3칸이 한 등급입니다.

1. **협업 상대 등급** — `tiers.json` 에 들어 있고 직접 고칠 수 있습니다 (`"A+"` 처럼 +/− 도 가능).
   협업 상대가 둘 이상이면 가장 높은 등급에서 시작합니다.
2. **조정** (칸 수는 `tiers.json` 의 `adjust` 에서 변경)
   - 다자 협업 +2칸, 인기 실루엣(조던 1, SB 덩크, 코비) +2칸
   - 같은 협업 상대가 최근 1년 3회 이상 −2칸 (프로그램이 본 기록 기준)
   - 선착순 −2칸, 발매처 5곳 이상 −2칸, 재발매 −3칸
   - 의류 −2칸 — 같은 협업 상대라도 옷은 신발보다 웃돈이 작습니다. 나이키 피드의 의류 상품과,
     상품명에 후디·티셔츠·재킷·팬츠 같은 단어(`tiers.json` 의 `apparel_keywords`)가 있으면 적용
3. **수익 기준**
   - 예상 순수익 = 예상시세 × (1 − 판매수수료 6%) − 배송비 4,000원 − 정가
   - 예상시세가 없으면 칸별 배수로 추정합니다

     | | − | 기본 | + |
     | --- | --- | --- | --- |
     | S | 1.66 | 1.8 | 1.98 |
     | A | 1.31 | 1.4 | 1.52 |
     | B | 1.10 | 1.15 | 1.23 |
     | C | 0.97 | 1.0 | 1.05 |

   - 최소 순수익·수익률 미달이면 등급과 상관없이 **패스**
   - 통과하면 A− 이상 → **추천**, 그 아래 → **애매**

예전 버전이 만든 `tiers.json` (S/A/B/C만 있는 형식)도 그대로 읽히며, 없는 항목과 새로 추가된
기본 협업 상대(예: Pharrell)는 기본값으로 채워집니다. 직접 고친 등급은 유지됩니다.

판매수수료·배송비는 `settings.json` 에서 바꿀 수 있습니다. 플랫폼 수수료는 바뀌므로
쓰는 곳의 현재 요율로 맞추세요.

## 시세 학습 (추정치 보정)

등급표 배수는 출발점일 뿐이고, **실제 시세 기록이 쌓이면 그 기록에 맞춰 추정이 보정**됩니다.

- **기록 넣는 곳**
  - `prices.csv` — 이미 발매된 제품의 `상품명, 정가, 시세, 기록일, 메모`. 크림에서 본 최근 체결가를 적으면 됩니다.
  - `releases.csv` 의 `예상시세` — 적어둔 시세도 자동으로 기록에 들어갑니다.
- **보정 방식**
  - 기록마다 "실제 시세 ÷ 등급표 추정"으로 등급표가 얼마나 틀렸는지 계산합니다.
  - 협업 상대별로 모읍니다. 협업이 없으면 인기 실루엣별, 그것도 아니면 일반 발매로 모읍니다.
  - 기록이 적은 협업 상대는 **시장 전체 보정** 쪽으로 당겨서 계산합니다. 기록 3건이면 둘이 반반이고,
    많아질수록 그 협업 상대 자체 기록을 따릅니다. 시장 전체가 식으면 기록 없는 협업 상대도 같이 낮아집니다.
  - 기록이 하나도 없으면 등급표 배수 그대로입니다.
- **결과 화면**: 카드에 `Union LA 기록 4건 반영`, `전체 기록 12건 반영`, `등급표 추정`, `시세 기준`처럼
  추정 근거가 표시되고, 맨 아래 **시세 학습** 표에 협업 상대별 기록 수와 등급표 대비 보정 폭이 나옵니다.

## 알림

- **추천**이 처음 잡히면 1회
- 응모 마감 3시간 전 1회 (`remind_hours_before_end`)
- 애매도 받으려면 `settings.json` 의 `notify_maybe` 를 `true` 로

## 한계

- 협업 등급표는 2024~2026년 리셀 자료 + 판단으로 만든 **출발점**입니다. 시세 기록이 적을수록
  등급표 의존도가 커지므로, 관심 있는 협업 상대부터 `prices.csv` 에 기록을 채우는 게 좋습니다.
- 같은 제품을 `prices.csv` 와 `releases.csv` 예상시세에 둘 다 적으면 두 번 반영됩니다.
- 크림 시세는 자동으로 가져오지 않습니다 (공개 API가 없고 약관상 자동 수집이 제한됨).
- 나이키 피드 형식이 바뀌면 수집이 실패할 수 있습니다. 실패해도 프로그램은 멈추지 않고
  `[경고]` 로 알려주며, `releases.csv` 입력분은 그대로 판정합니다.

## 개발

```bash
python -m resell_radar run          # 데이터는 ./resell_radar_data/
pytest tests/test_resell_radar.py
```

외부 패키지 없이 파이썬 표준 라이브러리만 씁니다. exe 는
`.github/workflows/resell-radar-exe.yml` 이 윈도우 러너에서 PyInstaller 로 만듭니다.
