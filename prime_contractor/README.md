# 원청 찾기 (자동제어 판넬 제조사용) — 베타

안성에서 자동제어 판넬(배전반·MCC·계장반)을 만드는 회사가 **원청 한 곳에만
기대는 구조에서 벗어나기 위한** 도구입니다. 새 원청 후보를 찾고, 매출 장부로
얼마가 모자라는지 보고, 이번 주에 몇 곳에 연락해야 하는지까지 내려 줍니다.

## 받는 곳 — 지금은 베타

> https://github.com/Nuribboya/-/releases/download/finder-beta/PrimeFinder.exe

써 보면서 계속 고치는 중이라 **번호를 붙이지 않고 한 주소에 덮어씁니다.**
코드를 올리면 GitHub 가 자동으로 빌드해 이 자리를 새 파일로 바꿉니다.
창 제목줄의 `베타 · 09-23 17:40 a1b2c3d` 가 언제·어느 코드로 만든 건지입니다.

- 파이썬 설치 없이 돌아갑니다. 받아서 쓰던 파일에 덮어쓰면 됩니다.
- 처음 실행할 때 윈도우 SmartScreen 이 막으면 `추가 정보` → `실행`
  (서명 없는 개인 빌드라 그렇습니다).
- 베타에서는 '새 버전이 나왔습니다' 알림을 띄우지 않습니다. 새로 받고 싶을 때
  위 주소에서 다시 받으면 됩니다.
- 예전에 번호를 붙여 낸 `finder-v1.0.0 ~ v1.5.1` 은 시험 삼아 낸 것이니 무시하세요.

그 버튼은 "저장했습니다" 확인 문구를 보고 싶을 때만 누르면 됩니다.

## ★ 최우선 목표 — 원청 한 곳 의존도 낮추기

원청이 한 곳뿐이면 그 한 곳이 한두 달만 발주를 줄여도 바로 적자가 납니다.
매출 확대보다 **두 번째 원청 확보**가 먼저라, 목표를 의존도로 잡고 거꾸로
계산합니다.

```
필요한 신규 월매출 = 원청 매출 ÷ 목표 의존도 − 지금 월매출
필요한 새 원청 수  = 신규 월매출 ÷ 원청 한 곳당 월 발주   (기본 1천만 — 어림값)
연락해야 할 곳     = 새 원청 수 ÷ 연락→첫수주 전환율       (기본 30%×40%×50% = 6%)
주당 연락          = 연락해야 할 곳 ÷ 남은 주               ← 이번 주 할 일
```

고정비를 넣으면(② 탭) "지금 원청이 멈추면 매달 얼마 적자, 현금으로 몇 달
버팀"도 나옵니다.

### 영업 진행 기록

`후보 → 연락함 → 미팅 → 서류제출 → 등록완료 → 견적요청 → 첫수주` (+ `보류`).
① 탭 결과에서 골라 넣고, 단계·다음 할 일·날짜·결제조건을 적습니다.

- 날짜를 비우면 1주 뒤로 잡습니다. 날짜 없는 할 일은 잊히니까요. 지나면 빨간 줄.
- 보류로 돌려도 이미 지나온 단계는 전환율에 셉니다.
- 다섯 곳 넘게 쌓이면 **실제 전환율**을 보여 줍니다. 그 전엔 안 보여 줍니다 —
  두세 곳으로 '50%'라고 하면 오해를 삽니다.
- 저장 위치: `%APPDATA%\PrimeFinder\leads.json`. 파일이 깨져도 앱은 켜지고,
  깨진 파일은 지우지 않고 `leads.broken.json` 으로 옆에 둡니다.

## ① 일감 줄 회사 찾기

판넬 제조사의 원청은 결국 *판넬을 사서 현장에 넣는 쪽*입니다. 그래서 나라장터에서
**자동제어·계장·수배전 공사를 낙찰받은 업체**를 원청 후보로 잡습니다.

```
나라장터 낙찰정보 ─┐
                   ├─→ 업체별 집계 ─→ DART 업종·주소 ─→ 국세청 폐업 확인 ─→ 겹침 판정 ─→ 적합도
발주기관(수요기관) ─┘
```

### 케이씨그룹과 겹침 판정

| 판정 | 근거 | 기본 동작 |
|---|---|---|
| 계열사 의심 | 상호가 `케이씨`/`KC` 로 시작하거나 계열사 목록에 있음 | **제외** |
| 동일 업종 | 업종코드가 반도체·디스플레이 계열이거나 공고명에 `반도체·클린룸` 등 | 통과 |
| 인접 업종 | `전자재료·특수가스·2차전지·태양광` 등 | 통과 |
| 무관 | 겹치는 신호 없음 | 통과 |

기본은 **계열사만 제외**합니다 — 배전반으로 넓히면서 반도체 쪽 원청도 보려는
목적이라서입니다. 반도체까지 빼려면 화면에서 '반도체 쪽은 다 빼기'.
겹치는 곳은 감점이 아니라 목록에서 뺍니다. 감점으로 섞으면 조건이 순위에 묻힙니다.

### 적합도 (100점 + 등급)

| 축 | 배점 | 묻는 것 |
|---|---|---|
| 판넬 일감 | 30 | 우리가 만드는 물건이 실제로 들어가는 공사인가 |
| 일감 크기 | 25 | 그래서 판넬이 얼마어치나 나오나 |
| 거리 | 20 | 안성에서 다닐 만한가 |
| 꾸준함 | 15 | 한 번 뚫으면 계속 나오나 — 건수와 **발주처 수** |

**② 탭에서 매출 장부를 불러오면** '일감 크기'(클수록 좋다) 대신 **'규모 맞음'**
(우리 크기에 맞나, 25점)으로 봅니다. 둘을 같이 넣으면 여전히 큰 곳이 유리해져서
하나만 씁니다.

| 그 곳의 한 달 판넬 물량 ÷ 우리 월매출 | 점수 | 뜻 |
|---|---|---|
| 3% 미만 | 낮음 | 작아서 영업 들인 만큼 안 남는다 |
| **10~40%** | **만점** | 무리 없이 받으면서 의존도도 낮춘다 |
| 80% | 절반 | 지금 인력·자금으로 빠듯하다 |
| 100% 넘음 | 낮음 | 그 한 곳이 지금 매출보다 커서 **또 한 곳에 매인다** |

한 건의 판넬 몫이 우리 월매출의 1.5배를 넘으면 '자재 먼저 사 넣을 돈이
되나' 경고를 붙입니다. 기준은 `fitness.py` 의 `SCALE_CURVE`, `BIG_JOB_MONTHS`.
| 안전 | 10 | 케이씨그룹과 안 부딪히고, 회사 정보가 확실한가 |

'판넬 일감'은 공고명이 얼마나 직접적인지로 갈립니다. `배전반·제어반·MCC·큐비클`
이 적혀 있으면 확실, `자동제어·계장·PLC` 는 가능성 높음, `전기공사` 는 확인 필요.

| 등급 | 점수 | 뜻 |
|---|---|---|
| A | 75~ | 먼저 연락해 보세요 |
| B | 60~ | 연락해 볼 만합니다 |
| C | 45~ | 여유 있을 때 |
| D | ~44 | 지금은 아닙니다 |

표에서 회사 이름을 두 번 클릭하면 축별 점수와 근거가 나옵니다.
CSV 의 '확인하실 점' 칸(주소 미확인, 업종 추정, 1건뿐 등)을 꼭 보세요.

### 제안서 만들기

표에서 회사를 고르고(Ctrl+클릭으로 여러 곳) `제안서 만들기`를 누르면,
회사마다 한 장짜리 제안서 초안을 텍스트 파일로 만들어 줍니다.

- **그 회사 얘기로 시작**: 낙찰받은 공사 중 가장 큰 건(발주처·공고명)을
  근거로 듭니다. 낙찰 이력이 없으면 일반적인 협력 제안 문구로 대체합니다.
- **우리 회사 정보**: ① 탭 위쪽 '제안서에 넣을 우리 회사 정보'에 회사명·
  설립연도·보유 인증·대표 실적·담당자·연락처를 적어 두면 반영됩니다.
  비워 둔 항목은 그냥 빠집니다.

규칙으로 짜맞춘 초안입니다 — 상호명, 담당자 존칭, 과장된 표현은 보내기 전에
직접 확인하세요.

### 예상 판넬 일감 — 어림값

공사비 전부가 판넬은 아니라 공종·직접성별 비중을 곱합니다.

| | 판넬이 직접 적힌 공고 | 자동제어·계장 공고 |
|---|---|---|
| 물품 | 70% | 35% |
| 공사 | 25% | 15% |
| 용역 | 15% | 10% |

업계 통념 수준의 어림값입니다. 후보끼리 비교하는 용도로만 쓰세요.
(`fitness.py` 의 `PANEL_SHARE`)

### 업종은 '무엇을 수주했나'로 정합니다

| 근거 | 무게 |
|---|---|
| 수주 공고명·발주기관 | 1.2 |
| 업종코드 | 0.6 — '무엇을 만드나'지 '누구에게 파나'가 아니라서 |
| 상호 | 0.5 |
| `건설`·`엔지니어링` 같은 일반 명사 | 0.25 — 상호에 너무 흔해서 |

그래서 `○○종합건설`이 정수장 공사를 땄으면 상하수도·수처리로 분류됩니다.

### 조회 속도

90일 조회 한 번에 나라장터를 수백 번 부릅니다(업무 3 × 15일 구간 6 × 검색어 25).
예전엔 하나씩 차례로 불러 몇 분씩 걸렸습니다. 지금은

| | |
|---|---|
| 동시에 8개씩 부름 | 명세 한도(초당 30건) 안에서 초당 20건. 기다리는 시간이 겹친다 |
| 겹치는 검색어 제외 | 공고명은 부분일치라 `배전반`이 `수배전반`도 찾는다 (27 → 25개) |
| 지난 기간 결과 저장 | 사흘 넘게 지난 구간은 30일간 저장분을 쓴다. 끝난 낙찰은 안 바뀐다 |

흉내낸 응답으로 잰 결과: 첫 조회 약 7배, 두 번째 조회부터 약 38배 빨라졌고
결과는 같았습니다. 실제 나라장터 응답 속도에 따라 첫 조회는 30초~1분 안팎.

저장 위치 `%APPDATA%\PrimeFinder\cache\g2b` (인증키는 저장하지 않습니다).
이상하면 앱의 '저장해 둔 결과 무시하고 전부 새로 받기' 또는 `--fresh`.
`probe`(진단)는 늘 새로 부릅니다.

### 폐업한 곳 걸러내기

폐업조회 인증키를 넣으면 국세청에 사업자 상태를 물어봅니다. 낙찰 자료에
사업자번호가 같이 와서 따로 입력할 게 없습니다. 폐업은 빼고, 휴업은 남기되
'확인하실 점'에 적습니다(다시 열 수도 있으니까요).

**신용등급과 결제조건은 공개되지 않아 앱이 알 수 없습니다.** 현금이냐
어음이냐가 떼일 위험을 가르는 가장 큰 변수이니 직접 확인하세요.

### 민간 발주 원청 (기업 목록에서 찾기)

나라장터에는 공공 발주만 올라옵니다. 반도체 팹 같은 민간 물량은 DART
상장사(2천여 곳)를 업종코드로 훑어 찾습니다. 상장사만 보므로 비상장 원청은
관공서 공사 쪽 결과와 같이 보세요. 첫 실행은 몇 분 걸립니다.

## ② 매출 보고 채우기

### 매출 파일 — 쓰시던 엑셀 장부 그대로

`.xlsx` 를 그대로 고르면 됩니다(외부 라이브러리 없이 읽습니다). `.csv`
(`연월,매출,목표`)와 매출 앱의 `.json` 도 됩니다. 손으로 만든 장부에서 실제로
본 것들을 처리합니다.

| 장부에서 흔한 것 | 처리 |
|---|---|
| 한 행에 표가 좌우로 둘 (우리 매출 \| 거래처 마감) | 머리글에 '매출'이 든 쪽을 고른다 |
| 1~9월 합계가 '10월' 칸에 들어앉아 있다 | 맨 끝 값이 앞선 값들의 합과 같으면 뺀다 |
| 연도가 칸이 아니라 제목에 있다 | 시트명·제목·파일명에서 찾는다 |
| 시트가 여러 개 (부가세·연차표까지) | '월매출' 시트를 우선 |

합계 판정은 **맨 끝 한 줄만** 봅니다. 아무 칸에나 적용하면 3월 매출이 우연히
1·2월 합과 같을 때 3월이 사라집니다. 진행 중인 달은 계산에서 뺍니다.

### 지출 파일 불러오기 (선택) — 있으면 어림값 대신 실제 지출로

손익분기는 '고정비 얼마·재료비 몇 %'라는 **어림값**입니다. 전기요금·부가세·
인건비 등을 합친 실제 월별 지출 장부가 있으면, 그 달은 어림값 대신
**매출 − 실제 지출**로 정확한 손익을 계산합니다. 형식은 매출 파일과 똑같이
'1월' 옆 칸에 그 달 지출 합계만 있으면 됩니다 — 매출 장부를 읽는 것과 같은
로직(`expenses.py`)을 그대로 씁니다.

지출 자료가 있는 달과 없는 달이 섞여 있어도 됩니다. 자료가 있는 달만 실제
지출로, 나머지는 그대로 손익분기 어림값으로 계산합니다. 우선순위 진단
(아래)의 '비용부터 줄이기' 판단도 실제 지출이 있으면 그걸 우선합니다.

식대비·전기요금·부가가치세처럼 **항목이 여러 개로 나뉜 지출 장부**도
됩니다 — 같은 시트 안이든 다른 시트든, '1월' 형태로 잡히는 블록을 전부
찾아서 그 달끼리 더합니다(매출과 달리 지출은 항목별로 나뉘어 있는 게
보통이라 하나만 고르지 않습니다). '7월25일'처럼 날짜까지 적힌 라벨(부가세
납부일정 등)도 그 달로 잡습니다.

### 손익분기로 목표 잡기

평균이나 '작년+10%'는 근거가 약합니다. 대신 **고정비를 덮으려면 얼마를
팔아야 하나**를 목표의 바닥으로 씁니다.

```
손익분기 매출 = 월 고정비 ÷ (1 − 재료·외주비 비율)       ← 이 밑이면 적자
목표 매출     = (월 고정비 + 목표이익) ÷ (1 − 재료·외주비 비율)
```

표의 '예상 손익'에서 적자인 달은 진한 빨강, 목표만 못 채운 달은 연한 주황입니다.

손익계산서 세 숫자(매출·매출원가·판관비)로 채울 수도 있습니다. 단 제조업
매출원가엔 공장 인건비 같은 고정비가 섞여 있어, 흑자 회사라면 손익분기가
**실제보다 낮게** — 안전해 보이는 쪽으로 — 나옵니다. 아시는 대로 고쳐 쓰세요.

### 모자란 만큼 채울 회사

목표에 못 미친 달이 있으면 그 금액만큼 후보를 골라 줍니다.

```
한 달 예상 금액 = 예상 판넬 일감 ÷ 조회 개월수 × 연락했을 때 일이 올 확률
                                                (A 35% · B 25% · C 15% · D 8% — 어림값)
```

다 합쳐도 못 채우면 채운 척하지 않고 얼마가 모자라는지 말합니다.

### 우선순위 진단 — 회사 안쪽에서 뭐부터 챙길지

새 원청을 늘리는 건 ①·★ 탭이 맡고, 여긴 반대쪽입니다: **지금 있는 숫자로
비용·영업·인력 중 뭐부터 볼지** 순서를 매깁니다. 장부를 불러오면 자동으로도
한 번 돌지만, 직원 수를 적고 `진단하기`를 눌러도 됩니다.

| 순서 | 걸리는 조건 |
|---|---|
| 높음 | 마감된 달이 적자다 (지출 파일을 불러왔으면 실제 지출 기준, 아니면 손익분기 어림값 기준) |
| 중간 | 매출 자체가 최근 3개월 평균 대비 10% 넘게 줄었다(→ 영업 대응) · 재료·외주비가 매출의 70% 넘는다 |
| 낮음 | 매출이 늘며 직원당 매출도 늘고 있다(→ 증원 여력 검토) · 걸리는 게 없으면 "영업 확대에 집중해도 됩니다" |

**직원 수는 달마다 있는 값이 아니라 화면에서 한 번 받는 지금 값**이라,
'직원당 매출'의 오르내림은 사실 매출 자체의 오르내림과 같은 숫자입니다.
그래서 매출이 줄었다고 곧장 '인력이 남는다'고 권하지 않습니다 — 실제로는
원청 발주량이 준 것일 수 있어서, 매출이 주는 신호는 영업(일감) 쪽 우선순위로
잡고 직원당 매출은 참고 숫자로만 보여줍니다. 반대로 매출이 늘 때는 '지금
인력으로 감당되나' 확인해 보라는 낮은 우선순위로만 씁니다. 딥러닝이나 외부
데이터 없이, 지금 가진 장부 숫자만으로 어림잡는 규칙입니다 — `diagnosis.py`
참고.

#### AI에게 한 번 더 물어보기 (선택, Gemini 무료 API)

위 규칙은 미리 정해둔 조건만 본다. `Gemini API 키` 칸에 무료 키를 넣고
`AI에게 한 번 더 물어보기`를 누르면, 같은 숫자를 실제 언어모델(구글
Gemini)에 던져서 규칙이 놓칠 수 있는 패턴을 찾아보게 한다.

- 키는 [aistudio.google.com/apikey](https://aistudio.google.com/apikey) 에서 무료로 받는다.
- 인터넷 연결이 필요하고, 무료 한도를 넘기면 "오늘 무료 사용량을 다
  썼습니다" 라고만 알리고 규칙 기반 결과는 그대로 남는다.
- 키를 안 넣으면 이 버튼은 그냥 안내만 하고, 나머지 진단은 그대로 동작한다
  — 딥러닝처럼 미리 학습하는 게 아니라 매번 그 자리에서 한 번 물어보는
  것이라, 학습 데이터도 인터넷도 없이 쓰던 그대로 써도 된다.
- 장부·비용 숫자만 보내고 회사 이름·사업자번호 같은 건 보내지 않는다
  (`ai_insight.py` `build_prompt` 참고).

## 알아두실 점

- **나라장터는 공공 발주만** 담습니다. 공공 공사를 따내는 설비·전기 업체는
  민간 일도 같이 하므로 원청 후보 명단으로는 유효합니다.
- **DART 는 공시대상 법인만** 있습니다. 업종코드가 빈 회사는 상호·공사명으로
  짐작한 것이라 직접 확인이 필요합니다.
- **거리는 시군구 대표좌표 기준 직선거리**입니다.
- 연습용 가짜 자료로 나오는 회사는 **실제로 없는 곳**입니다.
- 화면(tkinter/ttkbootstrap)은 개발 환경에서 띄워 보지 못한 채 만들었습니다. 계산
  로직은 테스트로 막아 두었지만, 실제 렌더링(테마 적용, 레이아웃)은 직접 못 봤으니
  칸이 잘리거나 색이 이상하면 캡처를 보내 주세요.

## 개발

### 명령줄

소스에서 바로 앱을 띄우려면 화면 테마용 패키지가 하나 더 필요합니다 (`pip install ttkbootstrap`).
없어도 앱은 뜨지만 순정 tkinter 룩으로 돌아갑니다 — exe 로 받으신 분은 이미 들어 있어 신경 쓸 필요 없습니다.

```bash
python -m prime_contractor.gui                         # 앱
python -m prime_contractor.cli screen --offline        # 연습용 자료로 후보 찾기
python -m prime_contractor.cli probe                   # 나라장터 API 어디서 막혔나
python -m prime_contractor.cli gap --sales 장부.xlsx --fixed-cost 30000000 --variable-ratio 60
python -m prime_contractor.cli goal --sales 장부.xlsx --target-dependency 70 --months 12
python -m prime_contractor.cli leads move "○○전기" 연락함 --next "회사소개서 보내기"
```

인증키는 환경변수 `G2B_SERVICE_KEY`, `DART_API_KEY`, `NTS_SERVICE_KEY`.

### 빌드·배포

- **베타**: 브랜치에 push 하면 `.github/workflows/build-exe.yml` 이 윈도우에서
  빌드해 `finder-beta` 한 곳에 덮어씁니다. 올린 뒤 실제로 받아지는지 확인하고,
  안 받아지면 실패시킵니다(릴리스 파일 목록 API 는 늦게 갱신될 때가 있어 믿지
  않습니다).
- **정식**: `prime_contractor/__init__.py` 에서 `CHANNEL = "stable"`,
  `__version__ = "1.0.0"` → Actions 탭에서 `build-exe` 수동 실행에 `1.0.0` 입력.
  `finder-v1.0.0` 이 생기고, 정식 빌드부터 앱이 새 버전 알림을 띄웁니다.
- 내 PC 에서 직접: `build_exe.bat` → `dist\PrimeFinder.exe`.
