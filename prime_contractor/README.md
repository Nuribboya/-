# 원청 후보 탐색 (자동제어 판넬 제조사용)

안성에서 자동제어 판넬(배전반·MCC·계장반)을 만드는 회사가 **새 원청을 찾되,
기존 원청(KC그룹)과 업종이 겹치지 않는 곳만** 골라내기 위한 도구입니다.

## 어떻게 찾는가

판넬 제조사의 원청은 결국 *판넬을 사서 현장에 넣는 쪽*입니다. 그래서 나라장터에서
**자동제어·계장·수배전 공사를 낙찰받은 업체**를 원청 후보로 잡습니다.
(발주기관은 직발주 가능성이 있어 별도 구분으로 같이 보여줍니다.)

```
나라장터 낙찰정보 ─┐
                   ├─→ 업체별 집계 ─→ DART 업종코드·주소 보강 ─→ 업종 겹침 판정 ─→ 점수/순위
발주기관(수요기관) ─┘                                              (KC그룹 제외)
```

### 업종 겹침 판정 4단계

| 판정 | 근거 | 기본 동작 |
|---|---|---|
| `계열사 의심` | 상호가 `케이씨`/`KC` 로 시작하거나 계열사 목록에 있음 | **제외** |
| `동일 업종` | 업종코드가 반도체·디스플레이 계열이거나, 공고명에 `반도체·클린룸·웨이퍼` 등 | 통과 (`--exclude-same-industry` 시 제외) |
| `인접 업종` | `전자재료·특수가스·2차전지·태양광` 등 전후방 연관 | 통과 (`--strict` 시 제외) |
| `무관` | 겹치는 신호 없음 | 통과 |

기본값은 **계열사만 제외**입니다. 배전반으로 확장하면서 반도체 쪽 원청도 보려는
목적이라, 반도체 업종 자체는 후보로 남깁니다. 예전처럼 반도체를 통째로 빼려면
`--exclude-same-industry` 를 붙이세요.

겹치는 후보는 감점이 아니라 **아예 목록에서 뺍니다**. 감점으로 섞으면 "안 겹치는 곳"이라는
조건이 순위에 묻히기 때문입니다. 뺀 이유는 `--include-excluded` 로 CSV에서 확인할 수 있습니다.

### 적합도 평가 (100점 + 등급)

"72점"만 나오면 어디부터 연락할지 알 수 없습니다. 다섯 축으로 나누고 각 축의
근거를 같이 냅니다.

| 축 | 배점 | 묻는 것 |
|---|---|---|
| **품목** | 30 | 우리가 만드는 물건이 실제로 들어가는 일인가 |
| **물량** | 25 | 그래서 판넬이 얼마어치나 나오는가 |
| **접근성** | 20 | 안성에서 대응할 만한 거리인가 |
| **지속성** | 15 | 한 번 뚫으면 계속 나오는가 |
| **안전도** | 10 | 기존 원청과 부딪히지 않고, 정보가 믿을 만한가 |

**품목** 축은 공고명이 얼마나 직접적인지로 갈립니다.

| 단계 | 예 | 판정 |
|---|---|---|
| 직접 | `배전반`, `제어반`, `MCC`, `큐비클`, `전기실` | 판넬이 확실히 들어감 |
| 공정 | `자동제어`, `계장`, `감시제어`, `PLC` | 들어갈 가능성 높음 |
| 일반 | `전기공사`, `기계설비공사` | 확인 필요 |

**지속성**은 건수만 보지 않고 **발주처가 몇 곳인지**도 봅니다. 한 기관에서만
3건 받은 곳보다 세 기관에서 1건씩 받은 곳이 거래 기반이 넓습니다.

### 추정 판넬 물량

낙찰금액 전부가 판넬은 아닙니다. 공종과 직접성에 따라 비중을 곱합니다.

| | 직접 품목 | 공정 키워드 |
|---|---|---|
| 물품 | 70% | 35% |
| 공사 | 25% | 15% |
| 용역 | 15% | 10% |

> 업계 통념 수준의 **어림값**입니다. 실제 견적과 다르며, 후보끼리 비교하는
> 상대 지표로만 쓰세요. 비중은 `fitness.py` 의 `PANEL_SHARE` 에서 고칠 수 있습니다.

### 등급

| 등급 | 점수 | 뜻 |
|---|---|---|
| A | 75~ | 우선 접촉 |
| B | 60~ | 접촉 가치 있음 |
| C | 45~ | 여력 될 때 |
| D | ~44 | 보류 |

`--min-grade B` 로 B 이상만 볼 수 있습니다.

### 점수가 왜 그렇게 나왔는지 보기

```bash
python -m prime_contractor.cli screen --offline --explain 한빛
```
```
A등급 78.4점 — 우선 접촉
  평택 15km · 상하수도·수처리 · 2건 24.7억 · 추정 판넬 4.3억
  · 품목        24.0 / 30   판넬 품목 직접 명시 1건
  · 물량        17.4 / 25   추정 판넬 4.3억 (낙찰 24.7억 기준)
  · 접근성       18.0 / 20   평택 15km
  · 지속성        9.0 / 15   2건 / 발주처 2곳
  · 안전도       10.0 / 10   무관 / 확인된 정보 3/3
```

앱에서는 **표의 줄을 더블클릭**하면 같은 내용이 뜹니다.

CSV 에는 축별 점수·근거와 **주의사항**(주소 미확인, 업종코드 없음, 단발 1건 등)이
같이 들어갑니다. 점수만 믿지 말고 주의사항 칸을 꼭 보세요.

### 업종이 어떻게 정해지는가

같은 회사라도 **무엇을 수주했는지**가 업종을 결정합니다. 근거마다 무게가 다릅니다.

| 근거 | 무게 | 이유 |
|---|---|---|
| 수주 공고명·수요기관 | 1.2 | 그 회사가 실제로 어디에 납품하는지를 보여준다 |
| 업종코드 (KSIC) | 0.6 | '무엇을 만드는지'일 뿐, 납품처가 아니다 |
| 상호·등록 업종명 | 0.5 | 보조 근거 |
| `건설`·`엔지니어링` 같은 일반 명사 | 0.25 | 상호에 너무 흔해서 이걸 세게 보면 전부 건설업이 된다 |

그래서 `○○종합건설`이 정수장 공사를 따냈으면 **상하수도·수처리**로 분류됩니다.
건설·전기공사 업종코드(41·42)는 시공사면 거의 다 갖고 있어서 무게를 0.25로 더 낮췄습니다.

## 민간 발주 원청 찾기 (industry-screen)

나라장터에는 **공공 발주만** 올라옵니다. 반도체 팹처럼 민간이 발주하는 물량은
낙찰 데이터에 아예 안 잡히므로, 그쪽 원청은 업종 자체로 훑어야 합니다.

```bash
export DART_API_KEY='...'
python -m prime_contractor.cli industry-screen --sector 반도체 --within 70 --out 반도체원청.csv
```

DART 상장사 전체(2천여 곳)의 업종코드와 주소를 확인해서 후보를 만듭니다.
낙찰 이력이 없는 모드라 배점이 다릅니다 — 업종 45 / 거리 35 / 정보 확실성 20.

- 첫 실행은 몇 분 걸립니다. 받아온 기업개황은 캐시되어 다음부터는 빠릅니다.
- **상장사만 봅니다.** 비상장 중소 원청은 여기 안 잡히니, `screen` 결과와 같이 보세요.
- 시험 삼아 빨리 돌려보려면 `--limit-companies 300` 을 붙이세요.

## API 키 발급

| 키 | 발급처 | 필수 |
|---|---|---|
| `G2B_SERVICE_KEY` | [공공데이터포털](https://www.data.go.kr/data/15129397/openapi.do) → 「조달청_나라장터 낙찰정보서비스」 활용신청 | 필수 |
| `DART_API_KEY` | [opendart.fss.or.kr](https://opendart.fss.or.kr) 인증키 신청 | 선택 |

두 키 모두 무료이고 신청 즉시(또는 1~2시간 내) 발급됩니다.
조달청 키는 Encoding/Decoding 어느 쪽을 넣어도 됩니다 (퍼센트 인코딩을 자동으로 풀어 씁니다).

## 설정 바꾸기

`config.sample.json` 을 복사해서 쓰면 됩니다. 특히 이 두 가지는 실제 사정에 맞게 조정하세요.

- **`incumbent`** — 기존 원청 정의. 이 블록은 **통째로 교체**됩니다(빠뜨린 항목은 빈 값이 됨).
  KC그룹 계열사 상호나 업종코드를 더 정확히 아신다면 여기에 채워 넣는 편이 판정이 정확해집니다.
  실제 업종코드는 `python -m prime_contractor.cli dart-lookup 케이씨텍 케이씨이앤씨` 로 확인할 수 있습니다.
- **`sectors`** — 타깃 업종과 가중치. 이미 강한 업종은 가중치를 낮추고, 뚫고 싶은 쪽을 올리세요.

## 알아두실 점

- **나라장터는 공공 발주만 담습니다.** 민간 공장 증설 물량은 여기 안 잡힙니다.
  다만 공공 공사를 따내는 설비/전기 업체는 민간 일도 같이 하므로, 원청 후보 명단으로는 유효합니다.
- **DART는 공시대상 법인만** 있습니다. 비상장 중소업체는 업종코드가 안 붙고, 그 경우
  상호와 수주 공고명 키워드만으로 겹침을 판정합니다(= 판정 신뢰도가 낮음). CSV의 `업종코드`
  열이 비어 있으면 직접 확인이 필요한 건입니다.
- **거리는 시군구 대표좌표 기준 직선거리**입니다. 순위용 근사값이라 실제 주행거리와 다릅니다.
- 조달청 API는 `https` 가 아니라 `http` 이며 30 TPS 제한이 있습니다. 오퍼레이션 경로가
  개정될 때가 있어, 후보 경로를 순서대로 찔러보고 되는 것을 골라 쓰도록(probe) 되어 있습니다.
  전부 실패하면 어떤 경로에서 무슨 에러가 났는지 그대로 보여줍니다.
- `--offline` 데이터는 **가상 업체**입니다. 영업 리스트로 쓰지 마세요.
